# 설계

[English](ARCHITECTURE.md) | **한국어**

ORCA_auto는 독립 ORCA 입력 디렉터리를 검증하고 durable queue에 저장한다.
상주 worker가 작업을 인수하고 공유 실행 슬롯을 예약해 독립 generation에서 실행한 뒤
검증된 종료 기록을 게시한다.

## 책임 경계

| 구성 | 책임 |
| --- | --- |
| `cli*.py`, `activity/` | 사용자 명령·큐 조회·취소·서비스 검사 |
| `orca/` | ORCA 입력·실행·복구 정책·분석·보고서 |
| `core/` | 영속 큐·실행 슬롯·프로세스·경로·저장 |

의존 방향은 `orca` → `core`다. 도메인 코드는 CLI를 import하지 않는다.
7.0의 engine catalog에는 ORCA만 있으며 확장 로더와 워크플로우 구현은 없다.

## 제출과 실행

`orca/submission.py`가 입력 자원 준비와 실행 스냅샷 생성을 명시적으로 소유한다.
메타데이터 조립은 순수 함수다. 영속 enqueue가 소유권을 넘기기 전까지 제출자가
정리를 책임지며, 커밋 여부가 불명확하면 먼저 인수 상태를 확인한다.

worker는 큐 identity와 불변 입력·실행 파일 binding을 검증한 뒤 실행한다.
자식의 큐 행이 pending으로 돌아와도 실제 종료 처리가 끝날 때까지 추적한다.
미완료 종료 게시가 있으면 해당 디렉터리의 새 실행을 보류한다. 디렉터리 identity를
확정할 수 없거나 queued 게시가 실패하면 큐 전체의 새 인수가 차단될 수 있다.
실행 전 자원 부족은 계산 실패 대신 작업을 대기시킨다.

취소 관찰은 변경되지 않은 큐 스냅샷을 재사용한다. 종료 알림은 영속 전송 claim과
제한된 백그라운드 전송을 사용한다. 알림은 best effort이며 실행 슬롯을 붙잡지 않는다.

## 상태·근거·보고서

`orca/state.py`는 상태 변경, `state_reading.py`는 읽기, `report/publication.py`는
기계 보고서 게시를 소유한다. 작성·검증은 `report_fields.py`의 같은 순수 필드 정의를 쓴다.

보고서 조회는 상태·generation 소유권·경로·receipt를 검증하고 파일별 해시를 조회당
한 번 계산한다. 선택 입력은 소유권과 다른 산출물을 확인한 뒤 해시하며, 반환 전에
파일 identity를 다시 검사한다. receipt는 해당 조회 안에서만 재사용한다.
과학적 근거는 검증된 엔진 출력에서 얻으며 HTML·SI는 표시 계층이다.

## 조회와 운영

영속 JSON·상태가 정본이다. 재생성 가능한 SQLite activity 인덱스가 정렬·필터 조회를
지원하고, 영속 무효화 ticket이 상태 게시를 반영한다. `--refresh`는 미등록 실행을
발견한다. 초기 구성과 복구는 원본 이력을 읽는다.

운영은 외부 설정·상태를 사용하는 검증된 불변 wheel runtime을 준비할 수 있다.
서비스 상태는 실제 프로세스의 build와 설치된 unit을 비교한다. 전환은
[RUNTIME](RUNTIME.md)의 idle 절차를 따른다.

폐기한 워크플로우 marker는 실행을 거부하고 과거 파일을 보호하는 데만 읽는다.
과거 admission 필드는 읽을 수 있도록 유지해 기존 실행 슬롯이 집계에서 사라지지 않게 한다.
